# 학습지원

구글 계정으로 로그인해서 쓰는 **안드로이드 · iOS · 웹 학습 앱**입니다. 세 곳 모두 같은 계정·같은 데이터를 써요.
메인 화면에서 4개 부문(계획/스케줄 · 학습 · 수행/세특 · 공부 도구)으로 들어가 각 기능을 씁니다.

- 앱: **Expo(React Native) + TypeScript** — 코드 하나로 안드로이드·iOS(아이패드 포함)
- 계정·데이터: **Firebase** (구글 로그인, Firestore 데이터베이스) — 무료 요금제로 충분, 카드 등록 필요 없음
- PDF·학습 앱 파일: **내 구글 드라이브**의 `학습지원` 폴더
- 오프라인: 인터넷이 없어도 기기에 저장했다가 연결되면 자동 동기화

## 1. 기능 한눈에 보기

### 메인 화면
- 오늘 할 일 달성률 링, 오늘 공부 시간, 다음 일정
- 4개 부문 바로가기 + 빠른 실행(공부 시작 · 5분 예열 · 캘린더 · 카드 복습)
- **다가오는 일 · 2주 이내**: 수행평가 마감, 특별 일정, 시험 날짜를 D-day로

### 계획 / 스케줄
| 기능 | 설명 |
|---|---|
| **시즌** (기간 선택) | `1학년 1학기 중간고사`, `겨울방학`처럼 계획을 실행할 큰 단위. 학년+종류 빠른 설정, 시험 날짜(D-day), 목표, 이전 시즌 과목 불러오기, 보관함 |
| 과목 · 할 일 | 시즌 안에 과목(색 지정)을 만들고 그 아래 할 일을 추가. 여러 줄로 쓰면 한 번에 여러 개 추가 |
| **에너지 코스트** | 할 일마다 피로도 5단계. 에너지가 높을수록 과목 색이 **짙게**, 낮을수록 **옅게** 표시되고 위에서부터 정렬 |
| **캘린더 짜기** | 클로드 화면처럼 왼쪽에 할 일 목록(과목별), 오른쪽에 캘린더. **길게 눌러 끌어다 놓기**, 또는 탭 → 칸 탭으로 배치. 일/주/월 전환, 캘린더 안에서 시즌 전환, 블록 이동·길이 조절(아래 손잡이), 사이드바로 끌어오면 배치 해제, 아래쪽에 **완료된 일** |
| **오늘 실행** | 실제로 보면서 완료 체크하는 화면. 지금 할 일 카드, 타임라인, 다른 날 보기 |
| **장소 태그** | `#기숙사 #학교자습실 #집` 등. 장소 탭을 누르면 거기서 할 수 있는 일만 보이고, 미배치 일은 "지금 하기"로 바로 시작 |
| **실패! 화면** | 계획 시간이 지났는데 완료 체크를 안 했으면 앱을 열 때 빨간 화면. 이유 기록(시간 부족/피곤/하기 싫음…) + 후속 조치: 사실 했어요 · 빈 시간에 다시 · 내일 같은 시간 · 반으로 쪼개기 · 5분만 해보기 · 포기. '하기 싫었음'을 고르면 그 과목을 기피 과목으로 표시 |
| **잔디 히트맵** | 하루 달성률에 따라 GitHub처럼 초록색이 짙어짐 (계획 홈·통계·월간 캘린더 칸) |
| **헥사곤 스탯** | 완료한 일의 경험치를 과목 축 + 유형 축(암기·문제풀이 등)에 분배. 축별 레벨, 전체 레벨·칭호 |
| (추가) 자동 배치 | 에너지 높은 일은 집중 잘 되는 시간대에 먼저, 하루 최대량 안에서 자동 배치 |
| (추가) 5분 예열 블록 · 복제 | 블록 앞에 '5분만' 블록 넣기, 내일/다음 주/매일 반복 복제 |
| (추가) 계획 정확도 | 미루지 않고 끝낸 비율, 못 지킨 이유 통계 |
| (추가) 알림 | 블록 시작 N분 전 소리 없는 알림 |

|---|---|
| 파일 관리 | PDF 가져오기(여러 개, 폰의 파일 선택 창에서 구글 드라이브 안의 PDF도 고를 수 있음), 폴더, 이름 바꾸기, 옮기기, 삭제, 검색. PDF 원본은 **내 구글 드라이브 '학습지원' 폴더**에 저장돼 다른 기기에서도 열림 (삭제하면 드라이브 휴지통으로) |

## 나만 쓰는 경우 (스토어에 올리지 않음)

- **안드로이드**: 완전 무료. Play Console 가입 필요 없음. `eas build -p android --profile preview`로 만든 APK를 폰에 바로 설치하면 끝 (컴퓨터를 켜둘 필요 없는 독립 앱)
- **iOS**: 스토어에 안 올려도 아이폰·아이패드에 설치하려면 둘 중 하나
  1. Apple Developer Program(연 $99) 가입 → `eas device:create`로 기기 등록 → `eas build -p ios --profile preview` (Mac 없어도 됨, 1년 유지)
  2. 무료 Apple ID + Mac의 Xcode로 직접 설치 (7일마다 다시 설치해야 함, 앱 잠금 등 일부 기능 제한)
- **구글 로그인 동의 화면은 '게시(In production)'로**: '테스트' 상태로 두면 드라이브 권한이 7일마다 풀려요. 이 앱이 쓰는 권한은 '비민감' 범위라 게시해도 심사가 없어요
- **Firestore 보안 규칙은 꼭 적용**: 혼자 쓰더라도 데이터베이스는 인터넷에 열려 있어서, 규칙이 없으면 다른 사람이 접근할 수 있어요
- 무료 Expo 계정으로 한 달에 안드로이드 15번, iOS 15번까지 클라우드 빌드할 수 있어요

## 3. 설치

```bash
cd ultimate-study
npm install
npx expo install --fix        # Expo 버전에 맞게 패키지 버전 자동 정리
npm install -g eas-cli
eas login
```

`app.json`에서 바꿀 것:
- `expo.ios.bundleIdentifier`, `expo.android.package` → 예: `com.내이름.ultimatestudy`
- (원하면) `expo.name` 앱 이름

## 4. Firebase 설정

1. Firebase 콘솔 → 프로젝트 만들기
2. **Android 앱 추가** (패키지명 = `app.json`의 `android.package`) → `google-services.json` 받아 **프로젝트 폴더 맨 위**에 넣기
3. **iOS 앱 추가** (번들 ID = `ios.bundleIdentifier`) → `GoogleService-Info.plist` 받아 **프로젝트 폴더 맨 위**에 넣기
4. **Authentication → 로그인 방법 → Google 사용 설정**
   - 펼친 화면의 **웹 SDK 구성 → 웹 클라이언트 ID**를 복사해 `app.json`의 `expo.extra.googleWebClientId`에 붙여넣기
5. **Firestore Database 만들기** → 규칙 탭에 `firebase/firestore.rules` 내용 붙여넣고 게시
6. **Google Drive API 켜기** (PDF를 내 드라이브에 저장하는 데 필요)
   - [Google Cloud 콘솔](https://console.cloud.google.com) 위쪽에서 **Firebase와 같은 프로젝트**를 고르기
   - API 및 서비스 → 라이브러리 → `Google Drive API` 검색 → **사용**
   - 로그인할 때 "액세스 차단됨/테스트 중인 앱" 같은 화면이 나오면: Google 인증 플랫폼(OAuth 동의 화면) → 대상 → **앱 게시**. 이 앱이 쓰는 `drive.file` 권한은 Google 분류상 '비민감' 범위라 별도 심사 없이 게시돼요
7. **Android 구글 로그인용 SHA-1 등록**: 첫 빌드 후 `eas credentials` → Android → 키스토어의 SHA-1을 복사 → Firebase 프로젝트 설정 → Android 앱 → "디지털 지문 추가". 그리고 `google-services.json`을 **다시 받아서** 교체

## 5. 개발 빌드로 내 폰에서 실행

```bash
# 안드로이드: APK를 받아 폰에 바로 설치
eas build -p android --profile development

# iOS: 기기 등록 후 빌드 (Apple 개발자 계정 필요)
eas device:create
eas build -p ios --profile development

# 빌드를 폰에 설치한 뒤, 컴퓨터에서 개발 서버 실행 → 앱에서 QR/주소로 접속
npx expo start --dev-client
```

친구에게 나눠줄 테스트용 앱: `eas build -p android --profile preview` (APK)
스토어 배포: `eas build --profile production` → `eas submit`

## 6. 앱 잠금 설정 (선택)

**iOS (스크린 타임 API)**
1. `app.json`의 `react-native-device-activity` 항목에 `appleTeamId`(Apple 개발자 팀 ID)와 `appGroup`(예: `group.com.내이름.ultimatestudy`) 입력
2. 개발 중에는 바로 동작하지만, **TestFlight·앱스토어 배포**에는 Apple에 *Family Controls (Distribution)* 권한을 신청해 승인받아야 해요 (Apple Developer → Contact → Family Controls 요청)
3. 지금 당장 잠금 없이 빨리 빌드하고 싶다면: `app.json` plugins에서 `react-native-device-activity` 항목을 지우고 `npm uninstall react-native-device-activity` → 앱 잠금 화면은 "이 빌드에서는 쓸 수 없어요"로 표시돼요
4. iOS는 앱이 직접 잠금을 풀어야 해서, 시간이 지난 뒤 **이 앱을 한 번 열면 자동 해제**돼요

**Android (이 프로젝트의 `modules/app-blocker` 네이티브 모듈)**
- 앱에서 *사용 정보 접근*, *다른 앱 위에 표시* 권한을 허용하면 고른 앱을 열 때 잠금 화면이 덮여요
- 플레이스토어에 올릴 땐 이 두 권한과 포그라운드 서비스 사용 이유를 정책 양식에 설명해야 해요 (개인 설치용 APK는 상관없음)

1. **Firebase에 웹 앱 등록**: Firebase 콘솔 → 프로젝트 설정 → 일반 → 내 앱 → `</>`(웹) 아이콘 → 닉네임 입력 → 나오는 `firebaseConfig`의 값 6개(apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId)를 `app.json`의 `extra.firebaseWeb`에 그대로 옮기기
2. **GitHub 저장소 만들기**: github.com에서 새 저장소(예: `study`, **Public**)를 만들고 이 프로젝트 폴더 전체를 올리기 (`node_modules`는 자동 제외). Firebase 설정값은 공개돼도 괜찮아요 — 데이터는 보안 규칙이 지켜요
3. **Pages 켜기**: 저장소 Settings → Pages → Source를 **GitHub Actions**로. 이후 `main`에 올릴 때마다 `.github/workflows/deploy-web.yml`이 자동으로 빌드·배포해요 (Actions 탭에서 진행 상황 확인, 3~5분)
4. **로그인 허용 주소 추가**
   - Firebase 콘솔 → Authentication → 설정 → 승인된 도메인 → `아이디.github.io` 추가
   - [Google Cloud 콘솔](https://console.cloud.google.com) → API 및 서비스 → 사용자 인증 정보 → OAuth 2.0 클라이언트 ID의 **Web client (auto created by Google Service)** → 승인된 JavaScript 원본에 `https://아이디.github.io` 추가
5. `https://아이디.github.io/study/` 접속 → 구글로 로그인

알아둘 점
- 웹은 보안상 구글 드라이브 권한이 1시간마다 만료돼요. 로그인 직후엔 바로 되고, 이후 PDF를 열 때 "구글 드라이브 연결" 버튼이 나오면 한 번 눌러주면 돼요 (설정 화면에도 버튼 있음). 한 번 연 PDF는 브라우저에 저장돼서 다음부턴 바로 열려요
- 내 컴퓨터에서 먼저 확인하려면 `npm run web`
- 직접 빌드해서 올리고 싶으면: `EXPO_BASE_URL=/study npx expo export --platform web` → 생긴 `dist` 폴더 안의 파일을 올리고, `index.html`을 복사해 `404.html`도 만들기
- 저장소 이름이 `아이디.github.io`이면 주소가 `https://아이디.github.io/`가 돼요 (워크플로가 알아서 맞춰요)

## 7. 폴더 구조

```
app/                       화면 (expo-router: 파일 경로 = 화면 주소)
  index.tsx                메인
  failure.tsx              실패! 화면
  settings.tsx             설정
  planner/                 계획: 홈, 시즌 목록, 시즌 상세, 캘린더 짜기, 오늘 실행, 성장 스탯
  study/                   학습: 파일함, 필기(file/[id]), 덱, 복습, 학습 앱
  perf/                    수행/세특: 캘린더, 항목 상세(세특 기록장)
  support/                 공부 도구: 타이머, 집중 화면, 무음 타이머, 5분 예열, 리포트, 링크, 앱 잠금
src/
  lib/                     데이터 저장소(store), 로그인(auth), 파일, 알림, 간격 반복, 앱 잠금, 날짜·색
  components/              공통 UI, 그래프(잔디·헥사곤·막대), 드래그 캘린더
  features/                부문별 로직과 편집 시트
assets/engine/study-engine.html   필기 엔진 (PDF·펜·백지 복습·코넬·카드·스포트라이트)
modules/app-blocker/       Android 앱 잠금 네이티브 모듈 (Kotlin)
*.web.ts / *.web.tsx       웹에서만 쓰이는 대체 파일 (Firebase JS SDK 로그인·DB, 드라이브, 브라우저 저장소, iframe)
.github/workflows/         GitHub Pages 자동 배포
firebase/                  Firestore 보안 규칙
```

데이터는 `users/{내 uid}/...` 아래에만 저장되고, 보안 규칙상 본인만 읽고 쓸 수 있어요. 손글씨는 페이지마다 `ink` 문서로 Firestore에, PDF·학습 앱 HTML은 **각자의 구글 드라이브 `학습지원` 폴더**에 저장돼요. 앱은 `drive.file` 권한만 받아서 **자기가 만든 파일만** 볼 수 있어요 (드라이브의 다른 파일은 못 봐요).

## 8. 알아두면 좋은 점 · 다음에 하면 좋은 것

- **PDF 엔진(pdf.js)은 처음 열 때 인터넷에서 받아요** (jsDelivr CDN, 이후엔 캐시). 완전 오프라인이 필요하면 `pdfjs-dist`를 앱 에셋으로 넣는 작업이 다음 단계예요
- 드라이브 '학습지원' 폴더에 컴퓨터로 직접 넣은 PDF는 앱에 자동으로 나타나지 않아요 (`drive.file` 권한 특성). 앱의 'PDF 가져오기'에서 드라이브를 골라 가져오면 돼요
- 드라이브에서 파일을 직접 지우면, 그 파일이 저장돼 있지 않은 다른 기기에서는 열 수 없게 돼요
- 손글씨 한 페이지는 Firestore 문서 한 개(최대 1MB)에 저장돼요. 한 페이지에 아주 빽빽하게 쓰면 한도에 가까워질 수 있어요
- 아직 없는 것: 올가미(선택해서 옮기기) 도구, 노트 공유, 열품타식 스터디 그룹/랭킹, 위젯
- 이 프로젝트는 **Expo SDK 54** 기준으로 작성했어요. 더 새 SDK로 올리려면 `npx expo install expo@latest --fix` 후 `npx expo-doctor`로 점검하세요
- 개발 중 오류가 나면: `npx expo-doctor`로 버전 점검, iOS 빌드 오류 시 `expo-build-properties`의 `useFrameworks: "static"` 설정이 있는지 확인 (React Native Firebase 필수)

## 9. 검증 상태

- 웹 버전처럼 다른 주소의 iframe 안에 필기 엔진을 띄웠을 때도 PDF 표시·필기·메시지 전달이 되는 것, 학습 앱이 격리된 iframe에서 저장 기능을 쓰는 것을 크롬에서 확인했어요
- 필기 엔진(`study-engine.html`)은 실제 크롬 브라우저에서 한국어 PDF로 자동 테스트했어요: PDF 표시, 펜(필압)·형광펜·지우개·실행 취소, 텍스트 선택→카드, 영역 캡처→이미지 카드, 스포트라이트, 손가락 스크롤·두 손가락 확대, 백지 복습 원본 대조·채점, 코넬 암기 모드·마인드맵·카드 내보내기
- 앱 코드 전체는 타입 검사(TypeScript)를 통과했어요
- 실제 휴대폰 빌드와 웹 빌드(`expo export`)는 이 작업 환경에서 할 수 없어서 아직 확인하지 못했어요. 첫 빌드에서 패키지 버전 문제가 나오면 `npx expo install --fix` 후 다시 빌드해 보세요
